# Overload — workout tracker (PWA)

A mobile-first, installable, offline-capable workout tracker. Plan your week, log sets with a rest timer, get double-progression suggestions, see PRs and charts, and track body measurements and simple habits.

**Runs entirely on free tiers:** GitHub Pages hosts the app, and Firebase (Spark plan) provides Auth + Firestore. There are no Cloud Functions and nothing paid.

- React + Vite + TypeScript, Tailwind CSS v4, Recharts, vite-plugin-pwa
- Firebase Auth (Google + email/password) and Firestore with offline persistence
- HashRouter (`/#/plan`), so routing works on GitHub Pages without server rewrites

---

## Features

| Area | What you get |
|---|---|
| Plan builder | Multiple plans; any number of days (training or rest) with custom names and weekdays; reorder days and exercises; several sessions per day; sets × rep range; seconds-based holds; per-side reps; supersets (2+ exercises, rounds); "drop set on last set"; per-exercise rest override; notes; one-tap **Swap** |
| Exercise library | Search, filter by muscle, add/edit/delete (with a warning if a plan uses it), quick-create from any picker |
| Logging | Today's session is suggested by weekday; you can pick any other day or start an empty workout. Weight/reps inputs have big ± buttons, and **last session's numbers** show above them. Includes per-exercise notes, drop sets, superset rounds, **auto rest timer** (vibrate + beep, ±15 s, survives screen lock), swap for today, add abs, and editing past workouts |
| Progression | Double progression: when every set hits the top of the range, it suggests +step (default 2.5 kg / 5 lb) and dropping to the bottom of the range. Otherwise it suggests holding the weight and beating your reps. Reps dropping 2 sessions in a row triggers a gentle food/sleep/recovery hint. PRs (weight, e1RM, reps-at-weight, volume) are highlighted with a trophy |
| Charts | Per exercise: heaviest, estimated 1RM, volume (with table view). Weekly sets per muscle group (last 6 weeks). Body weight and waist with goal lines |
| Body | Start/goal values, current, lost since start, left to goal, progress bar, and a reminder every N days (default 14) |
| Habits | Meals (0–3), protein meals (0–3), workout done (auto-ticked when you finish a workout), energy 1–5, and weekly summaries |
| Settings | kg/lb, in/cm, light/dark/system theme, rest defaults, progression step, week start |
| Data | Full JSON backup/restore. CSV export of workouts, body and habits. **CSV import** of past logs (Excel-style) or body measurements |
| Offline | Everything works offline; Firestore syncs when you're back online. Installable on Android and iOS |

There is also a **demo mode** (link on the sign-in screen) that stores data only in that browser, so you can try the app before setting up Firebase.

### Data model (Firestore)

```
users/{uid}/settings/app        units, theme, rest, progression step, start/goal values, active plan
users/{uid}/exercises/{id}      name, muscle, equipment, notes
users/{uid}/plans/{id}          name, days[ {name, weekday, rest, includeAbs, sessions[ {name, items[]} ]} ], absRoutine[]
users/{uid}/workouts/{id}       date (YYYY-MM-DD), title, entries[ {exerciseId, groupId, target, notes, sets[ {weight kg, reps, done, drop} ]} ]
users/{uid}/bodyLogs/{date}     weightKg, waistIn
users/{uid}/habitLogs/{date}    meals, proteinMeals, workoutDone, energy
```

**Keeping reads cheap:** a plan is one document, so loading it costs one read. Live listeners only cover the last 180 days of workouts and 120 days of habits. Older workouts are fetched on demand with date-range queries ("Load older" in History, 1Y/All in Progress, and once per session for all-time PRs). Weights are always stored in kg and waist in inches; units are converted for display only.

## 1. Firebase setup (one time, ~10 minutes)

> The Firebase web config keys are **public by design**: they ship inside the JavaScript bundle and only identify your project. Your data is protected by **Firebase Auth + `firestore.rules`**, which only let a signed-in user read and write `users/{their uid}/...`.

### 1.1 Create the project
1. Go to **https://console.firebase.google.com** and sign in with your Google account.
2. Click **Create a project** (or **Add project**).
3. Enter a name, e.g. `overload-tracker`, then click **Continue**.
4. On the Google Analytics step, switch **Enable Google Analytics** **off** (not needed), then click **Create project** and then **Continue**.
5. Check that the plan badge at the bottom-left says **Spark** (no-cost). **Do not upgrade.** Nothing in this app needs Blaze.

### 1.2 Enable Authentication
1. In the left menu, go to **Build → Authentication** and click **Get started**.
2. On the **Sign-in method** tab, click **Google**, toggle **Enable**, choose your **Project support email**, then click **Save**.
3. Click **Add new provider → Email/Password**, toggle **Email/Password** on (leave "Email link" off), then click **Save**.
4. Open the **Settings** tab, then **Authorized domains**, and click **Add domain**. Add `YOUR-GITHUB-USERNAME.github.io`, then click **Add**. (`localhost` is already listed, which is what local development uses.)

### 1.3 Create Firestore
1. In the left menu, go to **Build → Firestore Database** and click **Create database**.
2. If you're asked for an edition, pick **Standard**.
3. Choose a **location** close to you (e.g. `asia-south1 (Mumbai)` for South Asia) and click **Next**. *This can't be changed later.*
4. Choose **Start in production mode** and click **Create**.
5. Open the **Rules** tab, delete everything, paste the full contents of [`firestore.rules`](firestore.rules), and click **Publish**.

### 1.4 Register the web app and copy the config
1. Click the **gear icon** next to *Project Overview*, then **Project settings**.
2. Under **Your apps**, click the **Web** icon (`</>`).
3. Enter an app nickname, e.g. `overload-web`. **Don't** tick "Also set up Firebase Hosting". Click **Register app**.
4. You'll see a `firebaseConfig = { apiKey: "...", authDomain: "...", ... }` block. Keep this tab open, because you'll need these six values:

| Config field | Env var / GitHub secret name |
|---|---|
| `apiKey` | `VITE_FIREBASE_API_KEY` |
| `authDomain` | `VITE_FIREBASE_AUTH_DOMAIN` |
| `projectId` | `VITE_FIREBASE_PROJECT_ID` |
| `storageBucket` | `VITE_FIREBASE_STORAGE_BUCKET` |
| `messagingSenderId` | `VITE_FIREBASE_MESSAGING_SENDER_ID` |
| `appId` | `VITE_FIREBASE_APP_ID` |

## 3. Deploy to GitHub Pages (free)

### 3.1 Create the repository and push
1. On **https://github.com/new**, set **Repository name** to `overload` (any name works; the URL becomes `https://YOUR-USERNAME.github.io/REPO-NAME/`).
2. Choose **Public**. GitHub Pages on a free account requires a public repo. Your *data* is still private, because it lives in Firestore behind auth.
3. Don't add a README or .gitignore, since this project already has them. Click **Create repository**.
4. In this `overload` folder, run:

```bash
git init -b main
```

```bash
git add . && git commit -m "Overload workout tracker"
```

```bash
git remote add origin https://github.com/YOUR-USERNAME/overload.git
```

```bash
git push -u origin main
```

### 3.2 Add the Firebase secrets
1. In the repo, go to **Settings** (top tab), then **Secrets and variables → Actions** in the left menu.
2. Click **New repository secret**, set **Name** to `VITE_FIREBASE_API_KEY` and **Secret** to the `apiKey` value, then click **Add secret**.
3. Repeat for the other five: `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_APP_ID`.

### 3.3 Turn on Pages
1. Go to **Settings → Pages** (left menu).
2. Under **Build and deployment → Source**, choose **GitHub Actions**.
3. Open the **Actions** tab and click **Deploy to GitHub Pages**. If it hasn't run yet (or failed because the secrets weren't set), click **Run workflow → Run workflow**.
4. When both jobs are green, the URL appears on the **deploy** job, normally `https://YOUR-USERNAME.github.io/overload/`.

The workflow sets the Vite `base` path to `/<repo-name>/` automatically, or `/` for a `username.github.io` repo. It runs the unit tests before every deploy and copies `index.html` to `404.html` as a fallback.

### 3.4 Install on your phone
- **Android (Chrome):** open the URL, tap **⋮**, then **Install app** (or **Add to Home screen**).
- **iPhone (Safari):** open the URL, tap **Share**, then **Add to Home Screen**, then **Add**.

Sign in once while online. After that the app opens and logs workouts offline.

## Using it

- **First login** loads the default 6-day split (Sunday rest; abs on Mon/Wed/Fri), 43 exercises, and starting values (66 kg → 63 kg, waist 33 in → 32 in). Everything is editable.
- **Today** suggests the session for the current weekday. Tap **Start**, choose whether to include abs, and log.
- **Logging:** type a weight/reps or use ±, then tap ✓. Tapping ✓ on an empty row logs the greyed-out placeholder (your last numbers or the suggestion). The rest timer starts automatically. Supersets rest only after the last exercise in a round, and drop sets don't trigger a rest.
- **Suggestions:** a green "Go up" chip means you earned the weight increase; **Apply** fills it into the remaining sets.
- **Past workouts:** open one from History and change the date in **⚙ Workout details**.

### CSV import format

The importer reads the first row as headers (case-insensitive). The date is required, in `YYYY-MM-DD`, `DD/MM/YYYY` or `MM/DD/YYYY` form; you pick which, and Excel serial dates also work. The weight unit comes from the header (`Weight (kg)` / `Weight (lb)`) or from the toggle on the import screen.

| Layout | Example columns |
|---|---|
| One row per set | `Date, Session, Exercise, Set, Weight (kg), Reps, Drop, Notes` |
| Sets in one cell | `Date, Exercise, Sets` with `Sets` = `60x10, 60x9, 57.5x10` (`40x12x3` = 3 sets) |
| Wide | `Date, Exercise, Set 1, Set 2, Set 3` with cells like `60x10` |
| Body measurements | `Date, Weight (kg), Waist (in)` (no Exercise column) |

Blank Date/Exercise cells reuse the row above, as is common in Excel logs. Unknown exercise names are created (muscle "Other"; edit them later). Importing the same file twice replaces rather than duplicates. Use **Template** on the import screen for a ready-made example.

## Free-tier notes

The Spark plan allows 50k document reads, 20k writes and 1 GiB of storage per day/project. A typical day (opening the app a few times and logging one workout) uses roughly a few hundred reads and fewer than 100 writes, because:
- the plan is one doc, and settings are one doc;
- workouts are one doc each, written with a 400 ms debounce while you log;
- listeners cover only recent date ranges, and older data is fetched on demand;
- offline persistence serves repeat reads from the device cache.

No paid service is used or needed. If you ever want something that would require one (e.g. push notifications via Cloud Functions), that's a separate decision.

## Tests

`npm test` runs 36 Vitest tests:
- **progression.test.ts:** double progression (increase, hold, custom step, incomplete sets, drop sets ignored, bodyweight, rep cap), the recovery hint (two consecutive drops vs. one, weight increases don't count), PR detection (weight, e1RM, reps-at-weight, volume, first session never a PR), history extraction
- **stats.test.ts:** exercise series, weekly sets per muscle
- **importCsv.test.ts:** CSV quoting/delimiters, date formats, set notation, all import layouts, body files, error rows

## Security model

- `firestore.rules` allows access only to `users/{request.auth.uid}/...` and to the six known collections. Everything else is denied.
- No secrets live in the code or the repo. The `VITE_FIREBASE_*` values are public identifiers; they're kept in GitHub secrets only for tidiness.
- Optional hardening: in Google Cloud Console, go to **APIs & Services → Credentials**, open your Browser key, and restrict **HTTP referrers** to `https://YOUR-USERNAME.github.io/*` and `http://localhost:5173/*`.
